## Verified provider facts and limits

Official [USD-M connection rules](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/Connect) specify routed `/market` and `/public` endpoints, lowercase stream names, combined envelopes, 24-hour connection lifetime, server ping every 3 minutes and a 10-minute pong deadline. The documented limit is 10 incoming messages/s and 1024 streams/connection; it is not a market-event throughput guarantee. The worker composes subscriptions in URLs rather than repeatedly issuing control messages. Its 23-hour rotation is an application policy. Real native Node ping/pong operation remains untested here.

For 20 selected symbols the plan is **three sockets**: one shared two-stream universe ticker/funding connection, one 20-stream aggregate-trade connection and one 20-stream depth connection. All-universe coverage is discovered eligible active stablecoin-margined perpetuals; 522 is the previous website count, not a newly measured Binance count. Ticker coverage does not imply synchronized trade/book research coverage. Quiet omitted tickers can age stale under the conservative 5-second rule.

Official [local-book procedure](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/How-to-manage-a-local-order-book-correctly) requires buffering depth before snapshot, bridging U/u against snapshot ID and matching each subsequent pu to the prior u. Quantities replace levels; zero removes them; a gap requires resnapshot. The worker invalidates readiness and epochs rather than inferring missing continuity.

Current [REST catalog](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data) gives exchangeInfo weight 1; depth weight 2 for 5/10/20/50 levels, 5 for 100, 10 for 500, 20 for 1000. The worker uses 100 levels with 5 weight, at least 1 second pacing and a local 300 weight/minute budget. 20 initial snapshots cost 100 weight plus discovery before retries; shared-IP/provider limits still apply. 429/418 backoff is mandatory; repeated denials abort. The published normal depth excludes RPI orders, so this is not every form of exchange liquidity. No authenticated/private endpoints are needed.

## 24-hour measurement and abort plan

Use a dedicated approval record containing exact release SHA/bundle manifest, approved region, 20 symbols, maximum spend, start/end times, operator, public-only scope and retention decision. Measure for 24 hours from process start, allowing the first 120 seconds for warmup; capture at least 15-second health/resource samples and preserve gaps. Missing metrics or less than 24 hours is INCOMPLETE, never PASS. A full run includes the 23-hour planned connection rotation.

| Measure | Acceptance target after warmup | Abort/review |
|---|---|---|
| CPU / memory | CPU p95<=70%; RSS<=600 MiB | Higher p95 or any RSS breach; OOM/process restart aborts the run |
| Disk/network | Free disk>=2 GiB; network p95<=10 Mbit/s | Below disk floor or network budget breach; inspect provider usage |
| Heartbeat | Every 15 seconds, no gap>45 seconds | Missing/stale/future heartbeat or monitoring gap |
| Selected coverage | All 20 fresh and sequence-valid in >=95% sampled windows | Any symbol unavailable continuously 60 seconds, changed list, or coverage<95% |
| Required-input lag | p95<=2 seconds, every ready input<=5 seconds | Never label stale or unknown input ready |
| Queue | p95 age<=250 ms; ready age<=1 second; zero steady-state drops | Any new drop or age>1 second |
| Reconnects | Record every close/retry plus planned rotation | >6 disconnects in any rolling hour; policy/region denial; repeated 429/418 |
| Journal | Sink healthy, valid complete lines, 8 x 16 MiB bound | Write/fsync/rotation/incomplete-tail failure; do not clear evidence to resume |

Host/process resource metrics are distinct from application health. Collect Linux process CPU/RSS and disk/network counters with a separately reviewed read-only sampler or operator tool; the health file alone cannot prove CPU, RAM or network targets. Preserve timestamps, runId and counter baselines. Record planned rotation separately, but count its socket closes in the conservative reconnect budget. Never omit failed intervals. The offline `scripts/evaluate-market-soak.mjs` evaluates submitted NDJSON evidence; it does not collect missing host metrics, send alerts, start/stop services or certify reliability. A manual operator must enforce immediate aborts; delayed p95 assessment is a final acceptance check. No outbound notification channel is configured.

Evaluator rows have the exact shape `{at,health,resources:{cpuPct,rssMiB,networkMbps,diskFreeGiB}}`; `health` is the unmodified local health.json including runId and its own timestamp. Capture every 15 seconds using wall-clock milliseconds. CPU provenance: delta process user+system CPU ticks from `/proc/<pid>/stat`, divided by `CLK_TCK` and monotonic elapsed seconds, times 100 (one fully busy core = 100%, not normalized by host core count). RSS provenance: VmRSS from `/proc/<pid>/status`, KiB divided by 1024. Network provenance: non-loopback interface RX+TX byte delta, multiplied by 8 and divided by elapsed seconds and 1,000,000; this conservatively includes SSH/monitor traffic and is host traffic, not a claim of isolated worker bytes. Disk provenance: persistent filesystem available blocks times block size divided by 2^30. Record interface, PID, runId, sampling-tool version, clock/units and source commands privately with the evidence. Counter resets or PID/runId changes must not be smoothed away. A reviewed read-only sampler/operator must supply these values; none were captured from a remote host in this preparation.

Sample promptly when each 15-second health-file update appears, rather than repeatedly presenting an older file as new evidence. `at` must remain the actual collection time; do not rewrite it to the heartbeat timestamp. The evaluator adds heartbeat age to reported input lag, validates health version/runId and requires the exact proposed watchlist. A 30-second-old heartbeat can still be live under the 45-second liveness rule but cannot claim fresh input. A restarted/reset disconnect counter is not silently accepted. Measure real sampler scheduling delay and report it; these points do not imply a monitoring process has been deployed.
