## Baseline and destructive-change review

Read-only Staging aggregates showed two users, two legacy trading-settings rows, zero legacy credential rows, and zero executions. Incompatible environments, incompatible execution statuses, duplicate execution keys and unsafe legacy execution settings each counted zero. No user identifiers or credential values were inspected for the packet. Recheck the baseline at execution time.

- The ten files contain no top-level table drop, truncate, or row deletion. They replace constraints and a strategy policy and perform row backfills and full-table safety updates. Index builds, constraint validation and policy replacement can hold locks. Choose an approved change window and lock/statement limits.
- The local rehearsal caught a broken legacy credential copy in `202611100003`. The verified legacy schema has `updated_at` but no `created_at`. The corrected SQL preserves `updated_at` and uses the new row's insertion timestamp for `created_at`. This correction is only local. If another environment has recorded a different copy of this migration, reconcile that environment separately.
- These files are a migration sequence, not a replay or down-migration script. Some statements use `IF NOT EXISTS` or `ON CONFLICT`, but safety updates are re-applied on rerun and `202611110007` creates non-idempotent objects. A process interruption or ledger mismatch is a stop condition. Never retry every file, drop a relation to bypass drift, or repair the ledger without review.
- The local Admin Demo SQL stores ciphertext in restricted tables. Application encryption uses AES-256-GCM with `BINANCE_CREDENTIALS_KEY` on the server. A verified key, approved role privileges and actor-specific encrypted credential setup are still separate gates. Never read or print secret values for this check.
- Six common Admin Demo tables enable RLS and revoke browser grants. Composite foreign keys bind actor, provider and environment. The common RPC requires the service role and binds action, actor, provider, environment, scope, credential and session. The legacy RPC relies on its grant and service-side caller boundary. The common migration grants `service_role` full table privileges including audit mutation, and the audit data model has deletion dependencies. Treat durable append-only auditing as **unverified and blocked**. Review narrowed grants and retention behavior separately before any privileged activation.
- Signal history schema was installed earlier. The private public-market projection table is absent and remains outside this sequence. Its [review draft](../supabase/plans/public-market-pipeline.sql) still needs a least-privilege role/policy and a separate approval. A schema change alone establishes no signal freshness.
