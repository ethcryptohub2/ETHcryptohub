## Admin evaluation without signal writes

The Admin Scanner Management form calls `POST /api/admin/scanner-evaluation` after explicit interaction. Admin session, CSRF, exact Git SHA, exact deployment hostname and both Staging database identity checks are required. `SMARTEXIT_SCANNER_EVALUATION_APPROVED_SHA` and `SMARTEXIT_SCANNER_EVALUATION_APPROVED_UNTIL` are unset by default and distinct from the diagnostic and database-writing scan switches. For either public operation use a UTC expiry no more than 15 minutes ahead of execution, in a deployment-specific environment only. The expiry prevents reuse after the approved window even if the Preview remains addressable.

An approved run accepts one to three distinct enabled USDT perpetual symbols. It makes one ticker GET (40 weight) for the selected symbols and BTC context, then one `GET /fapi/v1/klines?symbol=…&interval=5m&limit=400` per selected symbol (2 weight each). Maximum four unsigned requests and 46 weight. Each response is capped at 1 MiB, with 3.5 seconds per request and a 15-second provider deadline. No fallback, redirects or retries. Provider denial or rate limit stops the batch. The request aborts if shared IP weight is missing or at least 300. At least 200 contiguous closed candles and the immediately preceding interval are required. Tickers must be at most five seconds old at evaluation time. One Staging PostgreSQL transaction-scoped advisory lock prevents simultaneous evaluation across Preview instances and holds for at least ten seconds from admission without writing rows. The control shows running state, timestamps, completed symbols and each strategy outcome.

After a successful separately approved ticker diagnostic, approve one evaluation on the exact Preview SHA and hostname using a named batch (start with BTCUSDT only, two requests and 42 weight). Confirm High-Risk 5m is enabled through read-only settings inspection. Scope the temporary approved SHA to Preview, verify the actual execution egress qualifies, execute one requested batch as Admin, and withdraw the gate. Treat HTTP 451 as an explicit regional restriction, HTTP 403 as denial of unspecified cause, 418/429 as rate limits, and report timeout, invalid data and application errors separately. Do not switch hosts to avoid a denial.
