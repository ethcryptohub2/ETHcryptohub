# Public worker isolation preparation

No host or persistent worker was activated. These changes prepare the existing public worker for a controlled local-journal soak, not website persistence or exchange execution.

## Prepared isolation layers

`scripts/build-public-worker-bundle.mjs <new-directory>` copies an explicit six-file allowlist: worker CLI, journal helpers, read-only health probe, public feed, public worker and type contracts. It does not copy `.env`, application routes, database/email/auth/order modules, dependencies, migrations or Git history. The new destination must not exist; preparation never merges into a checkout. MANIFEST.json records each file's SHA-256. It creates files locally only and never executes the bundle. Deploy this artifact, not the full application repository. Node24 is required; the artifact has no npm install/build hook or third-party runtime dependency.

The inactive systemd template uses `/usr/bin/env -i` and passes only the four explicit Staging worker configuration variables plus a fixed PATH. The CLI rejects credential-bearing environment names and provider-prefixed application configuration before filesystem/network access. Existing activation phrase, Staging environment and non-Vercel checks remain mandatory. No approval marker, activated config, service install/start, firewall change or remote filesystem write was performed.

The worker implementation sends only allowlisted public REST GETs to exchangeInfo/depth, forbids redirects, and constructs fixed public WebSocket subscriptions. No signed request, order endpoint, private stream, database client, SMTP/push client, migration runner or schedule is in the bundle. Journal and health writes are local state only. The prepared service has no boot install target. Environment rejection is defense in depth, not a kernel sandbox or a guarantee against arbitrary future code.

Before any authorized installation, use a dedicated unprivileged identity and host with no application or exchange credentials. Install the artifact root-owned with group `smartexit-market`, directories mode0750 and files mode0640; the local preparation defaults are private0600 and must be deliberately adjusted during authorized installation. Keep the state directory owned solely by the service identity, mode0700. Keep home directories hidden and audit all other readable host files, injected metadata credentials, mounts and network permissions. The current systemd sandbox constrains writes/capabilities, but it does not make every host file unreadable or restrict all outbound traffic at the kernel level. A firewall policy for public Binance/DNS/time endpoints requires separate review; DNS/IP changes mean a static IP allowlist must not be invented. Do not place Production secrets anywhere accessible to this identity.

## Test evidence and limits

Six new finite tests exercise the actual CLI with injected exchangeInfo/WebSocket/timer/signal fixtures: the proposed twenty-symbol three-transport plan without warmed coverage; clean start/stop and persisted run IDs; duplicate writer fencing; failed startup cleanup; crash-stale lock preservation; SIGTERM during discovery cancellation; credential rejection before I/O; exclusive allowlisted artifact creation. Existing worker/journal tests cover reconnect, stale feeds, overload, rotation, incomplete writes and draining. Run with `node --test scripts/public-worker-preparation.test.mjs lib/intelligence/market-worker*.test.mjs lib/intelligence/market-feed.test.mjs`.

Health includes a durable `runId` from epoch.json so external soak evidence can identify process restarts and cumulative-counter resets. Crash locks remain manual fail-closed review: never steal an active writer's lock. Startup cancellation waits for pending initialization before releasing the owned lock and closing the journal. Fixture success does not establish Linux systemd execution, live region access, ping/pong interoperability, sustained capacity or 24-hour reliability. Those remain explicit approved-host soak checks.
