# Test plan

Automated API tests run with `npm.cmd test` from the repository root. Tests use an in-memory SQLite database except the persistence/restart case, which creates an isolated temporary database and removes it afterward.

| Area                | Verification                                                                                                                                                                                                                                                                                                         |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Startup             | Health reports PAPER mode, connected SQLite, and live orders disabled                                                                                                                                                                                                                                                |
| Input validation    | Positive finite numbers, correct LONG/SHORT ordering, trailing range, request schemas                                                                                                                                                                                                                                |
| Trade milestones    | TP1 activates trailing; TP2 retains full quantity; TP3 closes full quantity                                                                                                                                                                                                                                          |
| Stops               | Initial and trailing stops close the full quantity; trailing stop is monotonic                                                                                                                                                                                                                                       |
| Idempotency         | Duplicate event ID does not alter trade state or add events                                                                                                                                                                                                                                                          |
| State safety        | Terminal state cannot receive another price update                                                                                                                                                                                                                                                                   |
| Cancellation        | Cancelling an open paper position closes the full quantity at its current simulated price and records realized P&L                                                                                                                                                                                                   |
| Risk                | Per-trade limit, open-position cap, daily loss block, kill switch                                                                                                                                                                                                                                                    |
| Persistence         | Open position and settings survive closing/reopening a SQLite connection                                                                                                                                                                                                                                             |
| Audit               | Creation and price milestone/stop events are queryable                                                                                                                                                                                                                                                               |
| Provider boundary   | NEAR testnet is displayed as the wallet-auth network; no-testnet explanation, official docs link, paper-setup action, empty tokens, and disabled swaps are clear and accurate                                                                                                                                        |
| Accounts/portfolio  | NEP-413 prefix/payload/signature encoding, direct wallet signing without a dApp contract, configured testnet/mainnet key lookup, origin validation, rate limiting, expired-session cleanup, CSRF origin rejection, account isolation, and P&L                                                                        |
| Wallet sign-in      | Meteor Wallet only, configured testnet network, account selection before signing, matching signed account, unsupported-signature error, and testnet login walkthrough                                                                                                                                                |
| Binance market data | Read-only USDⓈ-M active contracts, delivery contracts, per-quote volume ordering, quote-asset/volume/search filters, WebSocket/REST-driven paper exits, and quote conversion                                                                                                                                         |
| Market scanner      | Technical indicators and per-candidate signal reasons; volume/gainer/loser filters; timeframe freshness; funding/OI parsing; optional news, Glassnode exchange-flow and CoinGlass heatmap provider status; encrypted admin key management; provider failure and missing-key states                     |
| Portfolio reset     | Confirm authenticated reset removes that wallet's open/closed trades, events, P&L, and daily stats, restores $10,000, preserves risk settings, and does not affect a second wallet                                                                                                                                   |
| UI                  | Manual screen walkthrough at localhost:5173; verify wallet login, live prices/P&L, automatic paper TP/stop flow, open and closed dashboard positions, scanner signal/WAIT reasons, gainers/losers filters, reference entry/stop/targets, and provider status |
| Responsive UI       | At a 292px-wide browser viewport, dashboard, create, risk, and NEAR screens have no page-level horizontal overflow; at 1440px, the two-column layout remains within the viewport                                                                                                                                     |

Build verification scripts: `npm.cmd run lint`, `npm.cmd run typecheck`, `npm.cmd run build`. These are separate checks; the build-status document records only commands actually run.
